Kerberos

Kerberos is an open-source API gateway that sits between this app and your backend. It owns user accounts and sessions, checks every request before it reaches your services, and tells your backend who is calling.

Deployment modes

An organisation is the tenant boundary in Kerberos: users, groups and sessions never cross from one organisation to another, and every login names its organisation. You can run it two ways.

  • shield_personKerberos @for (org of exampleOrgs; track org) { groupsOrg {{ org }} }

    Multi-tenant

    One Kerberos serves many organisations, such as each customer of a SaaS product. Creating an organisation also creates its admin account, who manages that organisation's users and groups. The app works out the organisation at runtime, for example from a subdomain or an invite link, and your backend scopes its data by X-Krb-Org.

  • shield_personKerberos groupsOrg {{ orgId }}

    Single-tenant This starter

    The same model with exactly one organisation, hard-coded as orgID in src/environments/. Everyone who signs up joins that organisation. To go multi-tenant later, resolve the ID at runtime in AuthService instead of reading it from the environment; the API stays the same.

info In both modes, Kerberos must be the only way to reach your backend. The identity headers can only be trusted if nobody can call the backend without going through the gateway.
